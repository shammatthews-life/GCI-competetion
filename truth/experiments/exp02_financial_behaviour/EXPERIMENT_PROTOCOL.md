# EXP02 — Financial behaviour and affordability

## Status before execution

Predeclared experiment. No model has been trained and no acceptance decision
has been made. There will be exactly one primary notebook:
`EXP02_FINANCIAL_BEHAVIOUR.ipynb`. The notebook contains its full data,
feature, fold, training, prediction, verification, and hashing implementation;
it does not import experiment or project Python files.

## Hypothesis

Explicit financial ratios derived only from the provided application columns
may help a tree model represent affordability and repayment relationships
beyond the same model trained on the original supplied predictors.

This is a testable hypothesis, not a claim that the features improve default
risk prediction. It deliberately excludes the archived fee/product constants
because their permitted-data provenance has not been demonstrated.

## Data and feature definitions

Inputs are the official package's `train.csv`, `test.csv`, and
`sample_submission.csv`. No external data, downloaded artifacts, historical
predictions, or model checkpoints may be read. The target and ID are never
feature inputs.

The experimental block adds these deterministic rowwise features:

| Feature | Formula | Required denominator |
|---|---|---|
| `FIN_CREDIT_TO_INCOME` | `AMT_CREDIT / AMT_INCOME_TOTAL` | `AMT_INCOME_TOTAL > 0` |
| `FIN_ANNUITY_TO_INCOME` | `AMT_ANNUITY / AMT_INCOME_TOTAL` | `AMT_INCOME_TOTAL > 0` |
| `FIN_GOODS_TO_CREDIT` | `AMT_GOODS_PRICE / AMT_CREDIT` | `AMT_CREDIT > 0` |
| `FIN_CREDIT_TO_ANNUITY` | `AMT_CREDIT / AMT_ANNUITY` | `AMT_ANNUITY > 0` |
| `FIN_INCOME_PER_FAMILY_MEMBER` | `AMT_INCOME_TOTAL / CNT_FAM_MEMBERS` | `CNT_FAM_MEMBERS > 0` |
| `FIN_CREDIT_PER_FAMILY_MEMBER` | `AMT_CREDIT / CNT_FAM_MEMBERS` | `CNT_FAM_MEMBERS > 0` |
| `FIN_ANNUITY_PER_FAMILY_MEMBER` | `AMT_ANNUITY / CNT_FAM_MEMBERS` | `CNT_FAM_MEMBERS > 0` |

Non-finite inputs, missing values, and invalid denominators yield missing
ratios, not infinities. `FIN_CREDIT_TO_ANNUITY` is an amount ratio and is not
claimed to be a literal contract duration. No empirical fee, rate, cutoff,
quantile, or category-frequency constant is added.

## Matched evaluation

- Baseline: all supplied predictors except `SK_ID_CURR`; no engineered block.
- Candidate: the same predictors plus the seven predeclared financial
  features.
- Model: CatBoost GPU, fixed configuration in the notebook; no model zoo or
  hyperparameter search.
- Outer evaluation: five stratified folds, shuffle enabled, seed 42.
- Iteration selection: a fixed stratified 10% stopping split inside each
  outer training fold. Both variants use the exact same split and seed.
- Refit: train a fresh model on the full outer training fold at the selected
  iteration count. The outer validation labels never enter early stopping,
  feature selection, or training.
- OOF comparison: pooled AUC and all five paired per-fold AUC differences.
  No ensemble weights are tuned.
- Test predictions are produced by averaging the five outer-fold models.
  They are integrity-checked and saved as research arrays only; this
  experiment does not create a submission CSV.

The acceptance screen is a positive pooled OOF difference, mean paired fold
improvement of at least `+0.0002`, and improvement in at least 4/5 folds.
Passing this screen only yields `NEEDS_INDEPENDENT_SEED_REPLICATION`; it is
not acceptance. A separate seed replication, independent artifact
verification, and compliance checks are required before promotion.

## Leakage and rule controls

- The competition README bans external data and hand-labeling; all
  predictions must be automatically generated by a reproducible model.
- The course deck recommends features from existing features. Every added
  feature above uses only named supplied CSV columns.
- Transformations are deterministic rowwise arithmetic; there is no
  full-train, validation, or test-covariate fitting.
- No validation/test labels are available to the notebook.
- Categorical handling is delegated to CatBoost's fit-time categorical
  processing; outer validation/test rows do not fit preprocessing statistics.
- Raw IDs are checked for unique values and exact test/sample order, then
  excluded from model features.
- GPU must be the reported RTX 4050; execution fails if GPU evidence is
  unavailable. Utilization/VRAM are sampled during training and reported as
  sampled telemetry, not guaranteed true peaks.
- Record seeds, versions, input hashes, notebook-source hash, fold metrics,
  model configuration, and output hashes.

## Pre-run measurements

The provided training file contains 171,202 rows and 32 predictors; the test
file contains 61,500 rows. Financial denominators used by the proposed
features are positive in the observed training data; two
`CNT_FAM_MEMBERS` values are missing. Safe-ratio unit checks cover invalid
denominators regardless of these observed counts.

Label-free profiling also found that `DAYS_EMPLOYED == 365243` appears in
30,898 training rows. This is reserved for a separately declared research
hypothesis and is not used in EXP02.
