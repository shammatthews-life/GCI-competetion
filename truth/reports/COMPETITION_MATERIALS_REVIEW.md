## Rules stated by the competition README

`README.ipynb`, markdown cell 4 (`## Rules`) states:

1. **External data is prohibited at every analysis stage.** Use only the
   provided `input/train.csv` and `input/test.csv`.
2. **Hand-labeling is prohibited.** This includes manually assigning or
   changing any test predictions based on EDA-derived rules. Predictions must
   be automatically generated by a reproducible model that can be applied to
   similar data.
3. **Reproducibility is expected as much as possible.** Set random seeds.
4. **Referencing code is allowed, but attribution is required.** Record
   original sources; undisclosed copied code may jeopardize Honors/Outstanding
   recognition.
5. **Private sharing is permitted for this tutorial competition.** The README
   encourages public discussion, but this does not relax the data, prediction,
   or attribution rules.

The assignment text identifies `TARGET` as the training label, `1` as payment
difficulties, and `0` otherwise. It describes `test.csv` as data for evaluating
the trained model and gives ROC-AUC as the metric. Submissions must follow
`sample_submission.csv`: exactly `SK_ID_CURR,TARGET`; malformed submissions
receive -1. Public leaderboard scoring uses a subset to discourage
leaderboard overfitting; the final private leaderboard uses the full test
set. The last submitted file determines final ranking. No official score can
be inferred from OOF AUC.

For Honors/Outstanding recognition, the README requires code capable of
reproducing the submitted CSV. The course PDF's slides 17-18 demonstrate
uploading the code ZIP, slide 19 gives the stated deadline, and slide 20
directs participants back to the README and data dictionary for competition
rules and feature definitions.

## Tutorial review

The course tutorial is a beginner baseline, not a leakage-safe research
protocol. It uses five selected provided columns, explores missingness,
imbalance, distributions and outliers, then demonstrates label/count
encoding, train-mean imputation, car-age binning, standardization, logistic
regression, random forest, probability averaging, and sample-submission
formatting. The tutorial does not use external data or manually write test
predictions.

Its single stratified 70/30 holdout has seed 0. Before the holdout is created,
however, the example fits `ORGANIZATION_TYPE` count encoding, fills
`EXT_SOURCE_2` from the mean of all training rows, and fits `StandardScaler`
on all training rows. The validation partition therefore influences these
unsupervised preprocessing statistics. This is a useful introductory
walkthrough, but those steps must be fitted inside each training fold when
reporting unbiased OOF performance. Its one holdout and model-comparison
sequence are also not sufficient for extensive model selection.

The tutorial's `OWN_CAR_AGE >= 60` treatment is a reproducible transformation
based on feature inspection, not manual prediction labeling. It must not be
copied as a fixed rule without checking its provenance and validation
protocol. Likewise, the tutorial's train-fitted count encoder is an example,
not permission to use validation/test labels or an instruction to pool
validation/test covariates.

The PDF's slide 22 explicitly recommends creating features from existing
ones, including meaningful transformations or cross-features. Read together
with the README's external-data ban, this supports deterministic mathematical
features from the supplied columns; it does not justify importing outside
tables, hidden labels, outside cohort statistics, or undocumented empirical
constants.

## Input and data-dictionary findings

The distributed files contain 171,202 training rows, 61,500 test rows, and
32 predictor columns (plus `SK_ID_CURR`; training additionally has `TARGET`).
The "36 features" figure does not match these exact course-package CSVs.
The data dictionary describes the provided application, financial,
demographic, employment, region, phone/contact, and EXT_SOURCE fields.
Although `EXT_SOURCE_1`, `_2`, and `_3` are described as scores from external
sources, they are columns in the official supplied CSVs; using those columns
is different from obtaining the underlying external data.

Initial label-free profiling of the supplied training fields confirms that
credit, annuity, income, and goods price are finite and positive in all
171,202 rows. `CNT_FAM_MEMBERS` has two missing values. The directly
calculable ratios `AMT_CREDIT / AMT_INCOME_TOTAL`,
`AMT_ANNUITY / AMT_INCOME_TOTAL`, `AMT_GOODS_PRICE / AMT_CREDIT`, and
`AMT_CREDIT / AMT_ANNUITY` are finite for every row in this training file.
These observations support a small financial-ratio experiment; they do not
prove that any ratio improves AUC.

The supplied `DAYS_EMPLOYED` feature has a repeated value of `365243` in
30,898 training rows. This is a distributional anomaly worth a separately
predeclared, label-free follow-up; its meaning must not be asserted from
external lore or silently folded into the financial experiment.

## Compliance decisions for current work

| Technique or artifact | Status | Decision |
|---|---|---|
| Supplied train/test data only | **ALLOWED** | Use only the three local course CSVs; never fetch other Kaggle/Home Credit files or web data. |
| Deterministic ratios/log transforms of provided columns | **ALLOWED** | Predeclare formulas; guard missing/zero denominators; do not use outside empirical values. |
| Fixed fee `129.5` and product rate `0.0132` in the archived Phase 2 feature block | **UNVERIFIED — HOLD** | Available evidence calls these archived hypotheses and does not show they were derived solely from the supplied CSVs. Do not use in a competition submission unless their permitted-data derivation is demonstrated. |
| Test-covariate pooling/transductive statistics | **AMBIGUOUS — AVOID** | The README allows only the supplied files but calls test data evaluation data and does not explicitly authorize fitting transformations on test rows. New experiments fit transforms on their training partition and apply them to validation/test. |
| Nested target encoding using supplied training labels | **ALLOWED BY DATA-SOURCE RULE; NOT EXPLICITLY ADDRESSED** | It uses no outside labels, but must remain nested and fit-only. Never use validation/test labels. New feature hypotheses should prefer direct raw-column formulas when that suffices. |
| Manual test prediction overrides or EDA rules | **PROHIBITED** | Every prediction must come from the fitted model; no row-specific edits, thresholds, or hand-set labels. |
| Cross-validation early stopping on outer validation labels | **NOT ACCEPTABLE FOR OOF EVIDENCE** | This is an evaluation-method flaw even though the README does not define CV. Select iterations inside outer training data, then refit on the full outer training fold. |
| Source-code reuse | **ALLOWED WITH ATTRIBUTION** | Preserve source lineage and cite any copied external implementation; keep the submitted notebook reproducible. |
| Public-leaderboard-driven repeated tuning | **DISCOURAGED BY SCORING DESIGN** | Use frozen OOF protocols; the public score is only a subset and the last submission is final. |

These are conservative decisions from the available local materials, not legal
advice or a claim that the current Phase 2 candidate is organizer-certified.
In particular, the prior Phase 2 OOF score remains research-only while the
constant provenance and notebook reproducibility issues are unresolved.

## Experiment design adopted

The next experiment is one predeclared financial-behaviour block: ratios
calculated directly from `AMT_CREDIT`, `AMT_ANNUITY`, `AMT_INCOME_TOTAL`,
`AMT_GOODS_PRICE`, and `CNT_FAM_MEMBERS`, with guarded denominators. It will
use a same-model raw-column baseline, identical stratified folds and inner
stopping partitions, fold-only fitting, a fixed model configuration, and no
test-label or public-leaderboard selection. No fee/product constants,
outside data, test-set frequency fitting, manually specified predictions,
or OOF-tuned blend weights are part of that experiment.
