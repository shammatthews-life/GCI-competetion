The V43 architecture contains useful ideas—stronger tree capacity, multiple
model families, and row-level financial/external-score features—but its OOF
number cannot be treated as clean evidence:

1. At source line 1182, it concatenates train and test covariates before
   constructing multiple feature blocks. Person matching and group deviations
   consequently use other rows, including test rows. The supplied local rules
   do not settle whether this transductive fitting is allowed.
2. Its target encodings are generated at lines 677–746 using a five-fold split
   independent of the later outer-model folds. Outer validation labels can
   therefore affect encoded features used to evaluate that same outer fold;
   outer-training encodings can also incorporate labels from outer-validation
   rows. This invalidates the reported outer OOF estimate.
3. Multiview prediction features at lines 809–854 use another global
   five-fold process before the later outer CV. Those features are likewise
   not nested within the scored outer fold.
4. The softmax routing weights are optimized against the full OOF label vector
   at lines 1080–1116, then that same vector is used to report the routed OOF
   AUC. This is post-selection optimism, not nested meta-validation.
5. The final ensemble includes rank transforms. A strictly monotonic transform
   alone cannot improve AUC; only its use in a mixture that changes row order
   can affect AUC.

These are validation/rules-scope concerns, not a claim that the user's reported
public score is false. The feature zoo and model diversity may contribute
genuine signal, but V43 does not isolate those gains with a clean nested
ablation. A leaderboard score is also not a causal explanation of which
component helped.

## Phase 57 question

Does a compact, deterministic set of financial, timeline, external-score,
inquiry, missingness, and coarse Q3 features improve a matched CatBoost model
when validation is fold-isolated and cross-row features are excluded?

### Predeclared design

- **New standalone runner:**
  `experiments/phase57_rowwise_catboost/phase57_rowwise_catboost.py`
- **Two paired arms:** raw official predictors versus the same predictors
  plus 33 row-local derived features, including the coarse Q3 key.
- **Model:** CatBoost GPU, fixed 1,000 iterations, depth 6; same settings and
  folds for both arms; no outer-fold early stopping.
- **Categorical handling:** one-hot threshold 256; the runner checks every
  training category cardinality against the threshold and aborts rather than
  falling back to target statistics.
- **Validation:** five stratified folds, seed `20261113`; every model is fit
  only on its outer training partition. AUC/log loss are recalculated from
  saved OOF predictions.
- **Test output:** mean probability from the five candidate fold models. This
  is generated by the one standalone runner, not from blending CSVs.
- **Excluded:** train/test pooling, target encoding, entity matching,
  group-level aggregates, externally sourced data, previous predictions,
  leaderboard-guided adjustments, and rank blending.
- **Audit:** row/schema checks, synthetic feature self-test, GPU categorical
  preflight, input/source hashes, paired conditional bootstrap, submission
  order/range checks, and SHA-256 manifest.

The competition materials prohibit external data and hand-labeling but do not
settle every target-derived or transductive technique. Phase 57 avoids custom
target-derived features and pooled statistics. The result remains exploratory
because project labels/folds have prior exposure and no untouched holdout is
available.

### Phase 57 decision

- The 33-feature rowwise candidate improved its matched baseline by
  `+0.008300548` pooled AUC, was positive in `5/5` folds, and improved log
  loss by `0.002416264`. The 1,000-replicate conditional paired-bootstrap
  interval was `[+0.006743061, +0.009835467]`.
- This is a useful within-experiment feature result, not a causal ranking of
  every feature: the candidate adds a feature block, not one feature at a time.
- Its absolute `0.760616` OOF AUC is below Phase 56's Q3-only `0.762144` and
  the historical Phase 15 three-seed `0.768825`. Therefore it is **not a new
  best model**, does not explain V43's leaderboard claim, and its submission
  should not be promoted over stronger prior candidates without further
  controlled comparisons.
- The user reports Phase 57 scored `0.76528` on the leaderboard, versus
  `0.76732` for Phase 56 Q3 (a `-0.00204` change). The report records these as
  user-provided scores; the local files cannot verify the platform result.
  The Phase 57 OOF difference versus Phase 56 Q3 is `-0.001528`, and its
  average-precision difference is `-0.001746`, consistent with a weaker
  ranking model rather than a threshold-only issue. The user-reported V43
  score `0.77749` is likewise not independently verifiable here.

Phase 57's average precision was `0.244279`, below Phase 56 Q3's `0.246025`.
The top-decile metrics are nearly identical but slightly favor Phase 56 Q3.
At threshold `0.5`, both models have low recall because only `0.38%`–`0.40%`
of rows are called positive; this threshold is not appropriate for maximizing
recall. At the prevalence threshold, about one-third of rows are called
positive, illustrating that thresholded precision/recall depend strongly on
calibration/cutoff. Neither confusion matrix explains ROC-AUC by itself:
AUC measures pairwise ranking over all possible thresholds. The leaderboard
drop is consistent with the slightly lower OOF AUC and average precision of
Phase 57, not a threshold-selection problem.
