## Focused code review

### Fold-safe baseline and target encoding

`champion/EXP85_PHASE2_FROZEN_RELEASE/SOURCE/project/source/run_independent_baseline.py` constructs applicant-level deterministic features from each row, excludes TARGET from its feature builder, and creates stratified five-fold LightGBM/CatBoost models. Validation indices are separate for each fit. CatBoost/LightGBM use the validation fold for early stopping; this is conventional fold validation, but model selection across repeated experiments must not reuse the final evaluation folds.

`.../phase_02_fold_safe_key_encodings/run_experiment.py` creates combined train/test keys without labels, then calculates nested inner-OOF encodings only from training labels whose indices are disjoint from apply indices. Outer validation/test encodings are fitted from outer-training labels. The included test explicitly mutates apply-row labels and checks encoded outputs are unchanged. This is strong code-level evidence of fold safety for that helper, not proof of the complete experiment's result.

`screen_and_select_features.py` aggregates gain across five CV folds, selects one global top-550 set, then saves it for downstream modeling. That selection is not nested inside a later outer evaluation fold; downstream OOF scores using the selected set can inherit selection leakage. The available `nested_cv_feature_screening_benchmark.py` screens only inside each outer training partition, but compares against a hard-coded `full_screen_auc = 0.754136`.
